# RC1162 PRD：核账组合验收与迁移并发安全

## 问题

RC1161 已在生产启动路径注册耐久核账存储和只读订单证据提供器，但测试将存储重启与受保护 API 拆开，不能证明完整组合接线。旧 schema 的补列迁移使用“检查列后 ALTER”，并发实例可能同时观察列缺失并重复执行 DDL。

## 需求

1. 提供一个贯穿 production composition 到受保护管理 API 的隔离端到端测试，并覆盖案例/审计持久读回和进程存储重建后的读回。
2. 当 `Accounting`/`Gate` 未实现时，核账执行和解锁接口必须明确失败且不能产生成功状态或误导性审计。
3. 同时启动的 SQLite/MySQL 迁移必须安全、可重复；已有旧表补列与非竞态 DDL 错误必须有明确测试/错误语义。
4. 迁移/装配失败不得挂载不完整能力，任何问题保持交易封锁。

## 非功能与安全要求

- 数据库隔离、测试可重复且禁止破坏性操作真实 schema。
- 并发测试应有可控同步点，不靠短时间 sleep 证明竞态正确。
- MySQL DDL 的隐式提交和 advisory lock 生命周期须由实现/测试明确覆盖，不能假定跨 DDL transaction 回滚。
- 不输出密钥/凭据，不接真实交易所接口，不改变生产下单权限。

## Done Criteria

见 [验收标准](acceptance.md)。任何未覆盖的数据库/部署拓扑都必须明确标为未验收。
