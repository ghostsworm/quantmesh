# 可审计盈利证据契约（非盈利声明）

## 目的与边界

定义以后验证策略净收益所需的数据和复算方法。此文档本身、回测、纸交易或测试 fixture 均不能证明真实盈利。真实账户数据只有在用户明确授权/提供后方可纳入。

## 每个报告必须固定的实验身份

| 字段 | 要求 |
|---|---|
| 软件 | Git commit、发行版本、构建/二进制摘要、策略代码版本 |
| 策略 | 完整配置脱敏副本及 canonical hash、风险/额度参数、市场与执行模式 |
| 时间 | 交易所时间区间、UTC 归一规则、导入时间、时钟偏差与缺失窗口 |
| 账户范围 | 交易所、子账户/产品类型的脱敏稳定标识；绝不保存 API 密钥 |
| 原始证据 | 订单、逐笔成交、手续费、资金费、借款/还款/利息、转账与账户权益快照的来源和内容 hash |

## 复算口径

- 订单更新不可代替逐笔成交；每个 venue trade ID 在精确 owner 下唯一。
- 按费用原生资产记录数量和币种。只有权威数据明确证明为零时才能记零；缺字段必须标 unknown。
- 分离已实现毛 P&L、交易手续费、资金费、利息/借款成本和外部资金流；换算为报告计价币时保存价格来源、时间和转换误差。
- 已实现净 P&L = 已实现毛 P&L − 手续费 − 资金费 − 借贷利息 − 其它直接交易成本。未实现 P&L 单独显示，不混入已结算现金流。
- 权益变化须以期初/期末余额和持仓 mark-to-market 核账，并单列入金/出金/划转、奖励、清算和无法解释差额。
- 滑点须相对预先声明的基准价计算，保存基准来源/时间；不得事后挑选有利基准。
- 同时报告收益、最大回撤、波动/尾部损失、交易数、暴露时间、周转率、盈亏分布及分市场/策略归因；比较基准和验证区间须事先固定。
- 原始记录缺失、重复、owner 冲突、账户范围变更、费用未知、余额对不上或样本不足时，结果为 `INCOMPLETE/NOT_VERIFIED`，不得把缺值填零。

## 可由仓库验证与外部依赖

仓库可以通过 fixture、数据库集成和确定性复算验证唯一性、精度、幂等导入、对账方程、报告复现和不完整数据拒绝规则。真实交易收益、实际手续费/利息、滑点、账户余额/权益、税务成本与样本代表性必须来自经授权的真实账单与交易数据，并由独立复核确认；当前不具备此类证据。

## 当前代码审查发现（2026-10-11）

- `Trade`、`OrderFill`、profit API 的核心金额字段目前含 `float64`，与交易所原始十进制账单不保证无损；人工核账 evidence provider 对不能证明无损的值会拒绝，这是安全但未闭环。
- 逐笔成交模型有 TradeID 与部分费用估值字段，但缺少统一的 `CommissionKnown`（明确零与缺失不可混淆）；base-asset fee、第三资产估值证据也需端到端表示。
- `/api/profit/by-strategy` 目前实际按交易对汇总，却把 StrategyType 硬编码成 `grid`，会错误标注；不能作为策略归因证明。
- `storage/exporter.go` 导出 trades/orders/positions 的过滤能力不足以形成严格账户/Bot/时间范围证据包；`parseExportParams` 还允许查询参数覆盖当前配置账户标识。必须先做权限/tenant 边界审查并将完整范围下推到存储查询，不可依赖查询后截断或用户传入账户标识。
- `/api/profit/summary` 是当前汇总读 API，不是绑定输入快照 hash、覆盖区间和不完整项的不可变审计报告。
