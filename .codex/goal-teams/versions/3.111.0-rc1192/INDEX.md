## 目标

延续已确认顺序：先让收益完整性声明基于可枚举的原始账本与全部已知账户 scope，并明确权益勾稽尚无证据；再修复 FundingCarry 的人工恢复闭环中断点；最后交付固定版本策略验收报告。

## 当前已实施

- 收益查询从 raw `order_fills` 与 `trades` 两侧发现交易流；孤立成交、无效订单身份、订单方向/累计成交量不一致、未知手续费资产、手续费总额不一致均 fail-closed。
- 对数据库当前存在的账户 scope 与当前/显式归档 scope 做交叉核对，未归档或无归属历史不得被标记为账户历史完整。
- 账户权益样本与净外部资金流尚无可回溯的日级勾稽数据，因此累计及日/周/月收益完整/已核实标志保持 false。
- FundingCarry 已识别 durable `release_pending` 在旧 runtime 中断、且新 runtime 接管后无法继续的恢复缺口；尚未安全实现恢复协议。
- 策略验收报告仍明确未证明真实盈利，不把历史网格校准当作 FundingCarry 结果。
