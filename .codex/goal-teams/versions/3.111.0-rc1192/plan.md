# RC1192 执行计划

1. 收益口径：修复周期边界，覆盖原始成交流，交叉检查交易/成交/手续费与历史 scope；权益与净外部资金流没有逐日可复核来源时，禁止完整/已核实结论。
2. FundingCarry：为 durable `release_pending` 设计显式审计接管/续办协议。必须绑定相同 account scope、新 runtime generation、episode/hold revision、operation 与证据；接管撤销未消费 permit，保留旧 operation 与 hold，不自动重放订单；以 CAS 和独立读回消除旧 runtime 继续执行的可能。
3. 策略验收：固定源代码、配置、数据及成本假设；报告样本外净收益/回撤、风险与局限。当前证据不足时结论保持“未验收”。
4. 交付：按仓库规则更新版本、CHANGELOG、产品概览；定向与全量门禁通过后只提交本切片文件，保留既有未跟踪用户文件。rebase 到最新 `origin/main` 后推送；同 SHA 远端 CI 未全绿不合并。

## 风险控制

- 不通过“安全封锁”掩盖无法恢复；pending 状态必须有可审计续办或明确人工结案路径。
- 未验证成交数量/方向与策略归属前，不声称逐订单账完整；只验证手续费总和不足以证明订单级费用正确。
- CI、发布与真实账户盈利证据是不同验收层，不互相替代。
