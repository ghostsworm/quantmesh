## Review 结论

近期发力重点应是可信净收益、可审计异常恢复，以及证明策略在扣除成本后仍有优势。当前项目已有交易与恢复基础设施；在数据完整性和策略证据形成前，扩展策略数量或交易所覆盖不是优先项。

本次顺序沿用已确认的三阶段计划：

1. **净收益口径与报表**：修复跨月统计，约束完整性标记，明确趋势数据口径，并定义与账户权益/净外部资金流的勾稽边界。
2. **FundingCarry 人工核账与解锁**：验证生产装配、审计证据、持久化 CAS、精确 Gate 释放、重启/重复/并发及失败后的安全状态。
3. **策略验收报告**：锁定源码、配置、数据与成本假设，报告样本外收益、回撤和执行限制；没有真实账户证据时不作实盘盈利结论。

## 风险边界与已确认决定

- FundingCarry 事实修正采用追加、精确、可审计事件；不覆盖原始事实。
- 解锁仅允许已确认的精确恢复 Gate 来源；其他 manual/risk 来源继续阻断。解锁绑定 episode/account scope/runtime generation/revision/operation/actor/证据摘要，并需持久化读回。
- 操作人必须显式确认仓位与借贷均已清零，并提交外部核账材料摘要；系统不能将人工声明包装成交易所的独立真实性证明。
- UNKNOWN、部分成功、证据不完整、scope 不符、待处理 outbox 或 Gate 清理/读回异常都不得触发订单重放；失败时继续封锁或停在可审计的 pending 状态。
- PR #9 已合入 `main`（merge commit `1f1e8fac1b7978872def71f6252db135bf728672`）；远端 run `38508724174` 的 Test 与 Linux amd64 Build jobs 均成功。这只证明 PR #9 对应 SHA 的 CI，不是 RC1191 当前工作树的 CI，也不构成发布、实盘或盈利验收。
