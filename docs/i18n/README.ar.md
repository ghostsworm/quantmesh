## 📖 مقدمة

QuantMesh هو نظام صانع سوق للعملات المشفرة عالي الأداء ومنخفض زمن الاستجابة يركز على استراتيجيات تداول الشبكة الطويلة لأسواق العقود الدائمة. تم تطويره في Go ويعمل على تدفقات بيانات WebSocket في الوقت الفعلي، ويهدف إلى توفير دعم سيولة مستقر للبورصات الكبرى مثل Binance و Bitget و Gate.io.

بعد عدة تكرارات، استخدمنا هذا النظام للتداول بأكثر من $100 مليون في العملة الافتراضية. على سبيل المثال، تداول Binance ETHUSDC بدون رسوم، بفاصل سعر $1 و $300 لكل طلب، يمكن أن يتجاوز حجم التداول اليومي $3 مليون، وأكثر من $50 مليون شهريًا. طالما أن السوق يتأرجح أو يتجه صعودًا، سيستمر في توليد الأرباح. إذا انخفض السوق من جانب واحد، يمكن لـ $30,000 في الهامش ضمان عدم وجود تصفية لانخفاض 1000 نقطة. من خلال التداول المستمر لخفض التكاليف، يكون التعافي بنسبة 50% كافياً للوصول إلى نقطة التعادل، والعودة إلى سعر الفتح الأصلي يمكن أن يحقق أرباحًا كبيرة. إذا كان هناك انخفاض سريع من جانب واحد، سيقوم نظام التحكم في المخاطر النشط بتحديده تلقائيًا وإيقاف التداول فورًا، مما يسمح فقط بالطلبات المستمرة عندما يتعافى السوق، دون القلق بشأن التصفية من قمم الأسعار.

مثال: بدء تداول ETH عند 3000 نقطة، ينخفض السعر إلى 2700 نقطة، خسارة حوالي $3,000. عندما يتعافى السعر إلى ما فوق 2850 نقطة، يصل إلى نقطة التعادل. العودة إلى 3000 نقطة، تتراوح الأرباح من $1,000 إلى $3,000.

## ✨ الميزات الرئيسية

- **دعم متعدد البورصات**: متوافق مع Binance و Bitget و Gate.io و Bybit و EdgeX ومنصات رئيسية أخرى.
- **استجابة على مستوى الميلي ثانية**: مدفوع بالكامل بـ WebSocket (بيانات السوق وتدفق الطلبات)، مما يلغي تأخيرات الاستطلاع.
- **استراتيجية الشبكة الذكية**: 
  - **وضع المبلغ الثابت**: استخدام رأس مال أكثر قابلية للتحكم.
  - **نظام الفتحة الفائقة**: يدير حالات الطلب والمركز بذكاء، مما يمنع تعارضات التزامن.
- **نظام قوي للتحكم في المخاطر**:
  - **التحكم النشط في المخاطر**: مراقبة في الوقت الفعلي لشذوذ حجم K-line، وإيقاف التداول تلقائيًا.
  - **أمان الأموال**: يتحقق تلقائيًا من الرصيد والرافعة المالية ومخاطر المركز القصوى قبل البدء.
  - **المصالحة التلقائية**: مزامنة منتظمة لحالات المحلي والبورصة لضمان اتساق البيانات.
- **بنية تزامن عالية**: نموذج تزامن فعال يعتمد على Goroutine + Channel + Sync.Map.

## أفضل الممارسات

1. **لحالة VIP البورصة**: هذا النظام هو أداة توليد الحجم. إذا لم تكن تقلبات الأسعار كبيرة، يمكن لـ $3,000 في الهامش توليد $10 مليون في حجم التداول في 2-3 أيام.

2. **أفضل ممارسة للربح**: ادخل السوق بعد جولة من الانخفاض. اشترِ مركزًا أولاً، ثم ابدأ البرنامج. سوف يبيع تلقائيًا شبكة تلو الأخرى للأعلى. عندما يتم بيع مركزك بالكامل، أوقف النظام. إذا لم تكن متأكدًا مما إذا كان السوق الحالي نقطة منخفضة، يمكنك البدء بدون مركز أساسي. إذا انخفض أكثر، أضف مركزًا عند النقطة المنخفضة وأعد التشغيل للمتابعة البيع. هذا يزيد الأرباح إلى الحد الأقصى. كرر هذه الدورة للربح المستمر. لا تقلق بشأن الانخفاضات - البرنامج يخفض التكاليف باستمرار. طالما أنه يتعافى إلى النصف، تصل إلى نقطة التعادل.

## 🚀 البدء

### المتطلبات الأساسية
- Go 1.21 أو أعلى
- بيئة شبكة قادرة على الوصول إلى واجهات برمجة تطبيقات البورصة

### التثبيت

1. **استنساخ المستودع**
   ```bash
   git clone https://github.com/ghostsworm/quantmesh.git
   cd quantmesh
   ```

2. **تثبيت التبعيات**
   ```bash
   go mod download
   ```

### التكوين

> **Runtime SSOT:** The primary database table `app_config` holds the authoritative configuration. One-time YAML import: `./quantmesh --migrate-app-config` (with `QUANTMESH_IMPORT_YAML`, or `config.yaml` in the working directory), or run `./quantmesh /path/to/file.yaml` as the first argument. See [`docs/config-database-design.md`](../config-database-design.md).

1. نسخ ملف التكوين المثال:
   ```bash
   cp docs/config/examples/config.example.yaml config.yaml
   ```

2. تحرير `config.yaml` وملء مفتاح API ومعاملات الاستراتيجية:

   ```yaml
   app:
     current_exchange: "binance"  # حدد البورصة

   exchanges:
     binance:
       api_key: "YOUR_API_KEY"
       secret_key: "YOUR_SECRET_KEY"
       fee_rate: 0.0002

   trading:
     symbol: "ETHUSDT"       # زوج التداول
     price_interval: 2       # تباعد الشبكة (السعر)
     order_quantity: 30     # المبلغ لكل شبكة (USDT)
     buy_window_size: 10    # عدد أوامر الشراء
     sell_window_size: 10   # عدد أوامر البيع
   ```

### الاستخدام

#### وضع الإنتاج

تشغيل الملف الثنائي المترجم:

```bash
go run main.go
```

أو بناء وتشغيل:

```bash
go build -o quantmesh
./quantmesh
```

سيعمل الخادم الخلفي على تقديم الملفات الثابتة للواجهة الأمامية على المنفذ 28888 (افتراضي).

#### وضع التطوير

لتطوير الواجهة الأمامية مع إعادة التحميل السريع وتصحيح أخطاء الكود المصدري:

**الخيار 1: استخدام سكريبت التطوير (موصى به)**

```bash
./scripts/local/dev.sh
```

سيفعل هذا السكريبت:
- بدء خادم الخلفية Go على المنفذ 28888
- بدء خادم التطوير Vite على المنفذ 15173
- تمكين إعادة التحميل السريع لتغييرات كود الواجهة الأمامية
- توفير خرائط المصدر للتصحيح (لا يوجد كود مصغر)

ثم الوصول إلى التطبيق على: **http://localhost:15173**

**الخيار 2: بدء يدوي**

الطرفية 1 - بدء الخلفية Go:
```bash
go run main.go
```

الطرفية 2 - بدء خادم التطوير Vite:
```bash
cd webui
pnpm dev
```

ثم الوصول إلى التطبيق على: **http://localhost:15173**

**فوائد وضع التطوير:**
- ✅ إعادة التحميل السريع - تغييرات كود الواجهة الأمامية تنعكس فورًا
- ✅ خرائط المصدر - تصحيح مع كود TypeScript/React الأصلي (غير مصغر)
- ✅ تحديث سريع - مكونات React تتحدث دون فقدان الحالة
- ✅ رسائل خطأ أفضل - رؤية أسماء الملفات وأرقام الأسطر الفعلية

**ملاحظة:** في وضع التطوير، يقوم خادم التطوير Vite بوكيل طلبات API (`/api/*`) واتصالات WebSocket (`/ws`) إلى الخلفية Go التي تعمل على المنفذ 28888.

## 🏗️ البنية

يتبنى النظام تصميمًا معياريًا مع مكونات أساسية تشمل:

- **طبقة البورصة**: تجريد واجهة البورصة الموحدة، حجب اختلافات API الأساسية.
- **مراقب الأسعار**: مصدر سعر WebSocket فريد عالميًا، يضمن اتساق القرارات.
- **مدير المركز الفائق**: مدير المركز الأساسي، يدير دورة حياة الطلب بناءً على آلية Slot.
- **السلامة والتحكم في المخاطر**: تحكم في المخاطر متعدد الطبقات، بما في ذلك فحوصات البدء ومراقبة وقت التشغيل وكسر دائرة الشذوذ.

للحصول على وثائق بنية أكثر تفصيلاً، يرجى الرجوع إلى [ARCHITECTURE.md](../../ARCHITECTURE.md).

- ✅ **المعلومات الأساسية**: رقم الإصدار ونظام التشغيل والبنية ومعرف المثيل (UUID تم إنشاؤه عشوائيًا)
- ✅ **إحصائيات الاستخدام**: أسماء البورصات المستخدمة وأزواج التداول
- ✅ **مقاييس الأداء**: زمن استجابة طلب/استجابة API وزمن استجابة WebSocket
- ✅ **نشاط التداول**: اتجاه التداول (شراء/بيع)، باستثناء مبالغ التداول

**البيانات التي لا نجمعها:**
- ❌ **عنوان IP**: الواجهة الأمامية لديها التقاط IP معطل، الخلفية تستخدم معرف المثيل بدلاً من IP
- ❌ **الموقع الجغرافي**: لا يوجد جمع لخط العرض/الطول أو المدينة أو معلومات الموقع الأخرى
- ❌ **المعلومات الشخصية**: لا يوجد جمع لمعرفات المستخدمين أو رسائل البريد الإلكتروني أو الأسماء أو أي معلومات هوية
- ❌ **البيانات الحساسة**: لا يوجد جمع لمفاتيح API أو مبالغ التداول أو أرصدة الحسابات أو معلومات المركز
- ❌ **البيانات المالية**: لا يوجد جمع لأي معلومات مالية أو حساسة للتداول

### 🛡️ إجراءات حماية الخصوصية

1. **آلية معرف المثيل**: يستخدم UUID تم إنشاؤه عشوائيًا كمعرف فريد، مخزن في ملف `./data/instance_id`، لا يحتوي على معلومات شخصية
2. **IP الواجهة الأمامية معطل**: PostHog SDK مُكوّن بـ `ip_capture: false`، يعطل التقاط عنوان IP واستدلال الموقع الجغرافي
3. **الخلفية لا ترسل IP**: كود الخلفية لا يرسل عناوين IP إلى خدمة الإحصائيات
4. **اختياري تمامًا**: يمكن للمستخدمين تعطيل الإحصائيات في أي وقت عبر متغيرات البيئة
5. **شفافية الكود**: جميع كود الإحصائيات قابل للمراجعة، موجود في `utils/telemetry.go`

### ⚙️ كيفية تعطيل الإحصائيات

**الطريقة 1: متغير البيئة (موصى به)**
```bash
export QUANTMESH_DISABLE_TELEMETRY=1
```

**الطريقة 2: تعطيل الواجهة الأمامية**
في ملف `webui/.env.local`:
```bash
VITE_DISABLE_TELEMETRY=1
```

**الطريقة 3: تعديل الكود**
تحرير `utils/telemetry.go`، تعيين `Enabled` إلى `false`
