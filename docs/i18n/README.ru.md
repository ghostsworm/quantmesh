## 📖 Введение

QuantMesh — это высокопроизводительная система маркет-мейкера криптовалют с низкой задержкой, ориентированная на стратегии длинной сетки для рынков бессрочных контрактов. Разработанная на Go и работающая на потоках данных WebSocket в реальном времени, она направлена на обеспечение стабильной поддержки ликвидности для крупных бирж, таких как Binance, Bitget и Gate.io.

После нескольких итераций мы использовали эту систему для торговли более чем на $100 миллионов виртуальной валюты. Например, торговля Binance ETHUSDC с нулевой комиссией, интервалом цены $1 и $300 за ордер может превысить $3 миллиона дневного объема торгов и более $50 миллионов в месяц. Пока рынок колеблется или имеет восходящий тренд, он будет продолжать генерировать прибыль. Если рынок падает односторонне, $30,000 маржи могут гарантировать отсутствие ликвидации при падении на 1000 пунктов. Благодаря непрерывной торговле для снижения затрат восстановление на 50% достаточно для достижения безубыточности, а возврат к первоначальной цене открытия может принести значительную прибыль. Если происходит одностороннее быстрое падение, активная система управления рисками автоматически идентифицирует и немедленно останавливает торговлю, разрешая продолжение ордеров только когда рынок восстанавливается, без беспокойства о ликвидации из-за скачков цен.

Пример: Начало торговли ETH на уровне 3000 пунктов, цена падает до 2700 пунктов, потеря примерно $3,000. Когда цена восстанавливается выше 2850 пунктов, достигается безубыточность. Возврат к 3000 пунктам, прибыль варьируется от $1,000 до $3,000.

## 📜 Происхождение проекта

Этот проект изначально был разработан на основе [OpenSQT Market Maker](https://github.com/dennisyang1986/opensqt_market_maker), опубликованного [dennisyang1986](https://github.com/dennisyang1986) под лицензией MIT.

На основе оригинального проекта мы внесли следующие основные улучшения и расширения:

- ✨ **Полный интерфейс фронтенда**: Добавлен веб-интерфейс управления React + TypeScript, обеспечивающий визуальный мониторинг торговли, управление конфигурацией и анализ данных
- 🏦 **Расширение бирж**: Расширено с 3 бирж (Binance, Bitget, Gate.io) в оригинальном проекте до **20+ крупных бирж**
- 🔒 **Стабильность финансового уровня**: Комплексно улучшена надежность системы, включая комплексную обработку ошибок, механизмы безопасности параллелизма, гарантии согласованности данных, автоматическое восстановление и т.д.
- 📊 **Улучшенный мониторинг**: Улучшенная система логирования, сбор метрик (Prometheus), проверки работоспособности и предупреждения в реальном времени
- 🛡️ **Усиленное управление рисками**: Многоуровневый мониторинг рисков, автоматическая сверка, защита от аномалий и защита безопасности средств
- 🔌 **Система плагинов**: Поддержка расширяемых механизмов плагинов для легкой настройки и вторичной разработки
- 📱 **Поддержка интернационализации**: Многоязычный интерфейс (китайский/английский), поддержка i18n
- 🧪 **Поддержка тестовой сети**: Поддержка тестовых сетей нескольких бирж для разработки и тестирования

Для подробных описаний улучшений и информации о стороннем программном обеспечении см. файл [NOTICE](../../NOTICE).

## ✨ Ключевые функции

- **Поддержка нескольких бирж**: Совместим с Binance, Bitget, Gate.io, Bybit, EdgeX и другими крупными платформами.
- **Отклик на уровне миллисекунд**: Полностью на базе WebSocket (рыночные данные и поток ордеров), устраняет задержки опроса.
- **Умная стратегия сетки**: 
  - **Режим фиксированной суммы**: Более контролируемое использование капитала.
  - **Система супер-слотов**: Интеллектуально управляет состояниями ордеров и позиций, предотвращая конфликты параллелизма.
- **Мощная система управления рисками**:
  - **Активное управление рисками**: Мониторинг аномалий объема K-линии в реальном времени, автоматическая приостановка торговли.
  - **Безопасность средств**: Автоматически проверяет баланс, кредитное плечо и максимальный риск позиции перед запуском.
  - **Автоматическая сверка**: Регулярно синхронизирует локальные и биржевые состояния для обеспечения согласованности данных.
- **Архитектура высокой параллельности**: Эффективная модель параллелизма на основе Goroutine + Channel + Sync.Map.

## Лучшие практики

1. **Для статуса VIP биржи**: Эта система является инструментом генерации объема. Если колебания цен невелики, $3,000 маржи могут генерировать $10 миллионов объема торгов за 2-3 дня.

2. **Лучшая практика для прибыли**: Войдите на рынок после раунда падения. Сначала купите позицию, затем запустите программное обеспечение. Оно автоматически будет продавать сетку за сеткой вверх. Когда ваша позиция распродана, остановите систему. Если вы не уверены, является ли текущий рынок низкой точкой, вы можете начать без базовой позиции. Если он падает дальше, добавьте позицию в низкой точке и перезапустите, чтобы продолжить продажу. Это максимизирует прибыль. Повторяйте этот цикл для непрерывной прибыли. Не беспокойтесь о падениях - программа постоянно снижает затраты. Пока она восстанавливается наполовину, вы достигаете безубыточности.

## 🚀 Начало работы

### Предварительные требования
- Go 1.21 или выше
- Сетевая среда, способная получить доступ к API бирж

### Установка

1. **Клонировать репозиторий**
   ```bash
   git clone https://github.com/ghostsworm/quantmesh.git
   cd quantmesh
   ```

2. **Установить зависимости**
   ```bash
   go mod download
   ```

### Конфигурация

> **Runtime SSOT:** The primary database table `app_config` holds the authoritative configuration. One-time YAML import: `./quantmesh --migrate-app-config` (with `QUANTMESH_IMPORT_YAML`, or `config.yaml` in the working directory), or run `./quantmesh /path/to/file.yaml` as the first argument. See [`docs/config-database-design.md`](../config-database-design.md).

1. Скопировать файл примера конфигурации:
   ```bash
   cp config.example.yaml config.yaml
   ```

2. Отредактировать `config.yaml` и заполнить ваш API-ключ и параметры стратегии:

   ```yaml
   app:
     current_exchange: "binance"  # Выбрать биржу

   exchanges:
     binance:
       api_key: "YOUR_API_KEY"
       secret_key: "YOUR_SECRET_KEY"
       fee_rate: 0.0002

   trading:
     symbol: "ETHUSDT"       # Торговая пара
     price_interval: 2       # Интервал сетки (цена)
     order_quantity: 30     # Сумма на сетку (USDT)
     buy_window_size: 10    # Количество ордеров на покупку
     sell_window_size: 10   # Количество ордеров на продажу
   ```

### Использование

#### Режим продакшена

Запустить скомпилированный бинарный файл:

```bash
go run main.go
```

Или собрать и запустить:

```bash
go build -o quantmesh
./quantmesh
```

Бэкенд будет обслуживать статические файлы фронтенда на порту 28888 (по умолчанию).

#### Режим разработки

Для разработки фронтенда с горячей перезагрузкой и отладкой исходного кода:

**Вариант 1: Использовать скрипт разработки (Рекомендуется)**

```bash
./scripts/local/dev.sh
```

Этот скрипт будет:
- Запускать сервер бэкенда Go на порту 28888
- Запускать сервер разработки Vite на порту 15173
- Включать горячую перезагрузку для изменений кода фронтенда
- Предоставлять карты источников для отладки (не минифицированный код)

Затем получить доступ к приложению по адресу: **http://localhost:15173**

**Вариант 2: Ручной запуск**

Терминал 1 - Запустить бэкенд Go:
```bash
go run main.go
```

Терминал 2 - Запустить сервер разработки Vite:
```bash
cd webui
pnpm dev
```

Затем получить доступ к приложению по адресу: **http://localhost:15173**

**Преимущества режима разработки:**
- ✅ Горячая перезагрузка - Изменения кода фронтенда мгновенно отражаются
- ✅ Карты источников - Отладка с оригинальным кодом TypeScript/React (не минифицированным)
- ✅ Быстрое обновление - Компоненты React обновляются без потери состояния
- ✅ Лучшие сообщения об ошибках - Видеть фактические имена файлов и номера строк

**Примечание:** В режиме разработки сервер разработки Vite проксирует запросы API (`/api/*`) и соединения WebSocket (`/ws`) на бэкенд Go, работающий на порту 28888.

- ❌ **IP-адрес**: Фронтенд имеет отключенный захват IP, бэкенд использует ID экземпляра вместо IP
- ❌ **Геолокация**: Нет сбора широты/долготы, города или другой информации о местоположении
- ❌ **Личная информация**: Нет сбора ID пользователей, электронных писем, имен или любой идентификационной информации
- ❌ **Чувствительные данные**: Нет сбора API-ключей, сумм торговли, балансов счетов или информации о позициях
- ❌ **Финансовые данные**: Нет сбора какой-либо финансовой или торговой чувствительной информации

### 🛡️ Меры защиты конфиденциальности

1. **Механизм ID экземпляра**: Использует случайно сгенерированный UUID в качестве уникального идентификатора, хранится в файле `./data/instance_id`, не содержит личной информации
2. **IP фронтенда отключен**: PostHog SDK настроен с `ip_capture: false`, отключая захват IP-адреса и вывод геолокации
3. **Бэкенд не отправляет IP**: Код бэкенда не отправляет IP-адреса в службу статистики
4. **Полностью опционально**: Пользователи могут отключить статистику в любое время через переменные окружения
5. **Прозрачность кода**: Весь код статистики проверяем, находится в `utils/telemetry.go`

### ⚙️ Как отключить статистику

**Метод 1: Переменная окружения (Рекомендуется)**
```bash
export QUANTMESH_DISABLE_TELEMETRY=1
```

**Метод 2: Отключить фронтенд**
В файле `webui/.env.local`:
```bash
VITE_DISABLE_TELEMETRY=1
```

**Метод 3: Изменить код**
Отредактировать `utils/telemetry.go`, установить `Enabled` в `false`
