## 📖 はじめに

QuantMeshは、パーペチュアル契約市場向けのロンググリッド取引戦略に焦点を当てた高性能・低レイテンシの暗号通貨マーケットメーカーシステムです。Goで開発され、WebSocketリアルタイムデータストリームで駆動され、Binance、Bitget、Gate.ioなどの主要取引所に安定した流動性サポートを提供することを目指しています。

いくつかの反復を経て、このシステムを使用して$1億以上の仮想通貨を取引してきました。例えば、Binance ETHUSDCをゼロ手数料、$1の価格間隔、注文あたり$300で取引すると、日次取引量は$300万を超え、月間$5000万以上になります。市場が振動しているか上昇トレンドにある限り、利益を生み出し続けます。市場が一方的に下落した場合、$30,000の証拠金で1000ポイントの下落に対して清算を保証できます。コストを下げるための継続的な取引を通じて、50%の回復で損益分岐点に達し、元の開始価格に戻ると大幅な利益を得られます。一方的な急落がある場合、アクティブリスク管理システムが自動的に識別し、即座に取引を停止し、市場が回復したときにのみ継続的な注文を許可し、価格スパイクによる清算を心配する必要はありません。

例: 3000ポイントでETHの取引を開始し、価格が2700ポイントに下落し、約$3,000の損失。価格が2850ポイントを超えて回復すると、損益分岐点に達します。3000ポイントに戻ると、利益は$1,000から$3,000の範囲になります。

- 🛡️ **強化されたリスク管理**: 多層リスク監視、自動調整、異常回路遮断、資金安全性保護
- 🔌 **プラグインシステム**: 簡単なカスタマイズと二次開発のための拡張可能なプラグインメカニズムのサポート
- 📱 **国際化サポート**: 多言語インターフェース（中国語/英語）、i18nサポート
- 🧪 **テストネットサポート**: 開発とテストのための複数の取引所のテストネット環境のサポート

## ベストプラクティス

1. **取引所VIPステータスのため**: このシステムはボリューム生成ツールです。価格変動が大きくない場合、$3,000の証拠金で2-3日で$1000万の取引量を生成できます。

2. **利益のためのベストプラクティス**: 下落のラウンドの後に市場に入ります。まずポジションを購入し、次にソフトウェアを開始します。自動的にグリッドごとに上向きに売却します。ポジションが売り切れたら、システムを停止します。現在の市場が低点かどうか不明な場合は、ベースポジションなしで開始できます。さらに下落した場合は、低点でポジションを追加し、再起動して売却を続けます。これにより利益が最大化されます。このサイクルを繰り返して継続的に利益を得ます。下落を心配しないでください - プログラムは継続的にコストを下げます。半分回復する限り、損益分岐点に達します。

## 🚀 はじめに

### 前提条件
- Go 1.21以上
- 取引所APIにアクセスできるネットワーク環境

### インストール

1. **リポジトリをクローン**
   ```bash
   git clone https://github.com/ghostsworm/quantmesh.git
   cd quantmesh
   ```

2. **依存関係をインストール**
   ```bash
   go mod download
   ```

### 設定

1. サンプル設定ファイルをコピー:
   ```bash
   cp config.example.yaml config.yaml
   ```

2. `config.yaml`を編集し、APIキーと戦略パラメータを入力:

   ```yaml
   app:
     current_exchange: "binance"  # 取引所を選択

   exchanges:
     binance:
       api_key: "YOUR_API_KEY"
       secret_key: "YOUR_SECRET_KEY"
       fee_rate: 0.0002

   trading:
     symbol: "ETHUSDT"       # 取引ペア
     price_interval: 2       # グリッド間隔（価格）
     order_quantity: 30     # グリッドあたりの金額（USDT）
     buy_window_size: 10    # 買い注文数
     sell_window_size: 10   # 売り注文数
   ```

### 使用方法

#### 本番モード

コンパイル済みバイナリを実行:

```bash
go run main.go
```

またはビルドして実行:

```bash
go build -o quantmesh
./quantmesh
```

バックエンドはポート28888（デフォルト）でフロントエンドの静的ファイルを提供します。

#### 開発モード

ホットリロードとソースコードデバッグを備えたフロントエンド開発の場合:

**オプション1: 開発スクリプトを使用（推奨）**

```bash
./dev.sh
```

このスクリプトは:
- ポート28888でGoバックエンドサーバーを開始
- ポート15173でVite devサーバーを開始
- フロントエンドコード変更のホットリロードを有効化
- デバッグ用のソースマップを提供（ミニファイされていないコード）

次に、アプリケーションにアクセス: **http://localhost:15173**

**オプション2: 手動起動**

ターミナル1 - Goバックエンドを開始:
```bash
go run main.go
```

ターミナル2 - Vite devサーバーを開始:
```bash
cd webui
pnpm dev
```

次に、アプリケーションにアクセス: **http://localhost:15173**

**開発モードの利点:**
- ✅ ホットリロード - フロントエンドコード変更が即座に反映
- ✅ ソースマップ - 元のTypeScript/Reactコードでデバッグ（ミニファイされていない）
- ✅ 高速リフレッシュ - Reactコンポーネントが状態を失うことなく更新
- ✅ より良いエラーメッセージ - 実際のファイル名と行番号を表示

**注:** 開発モードでは、Vite devサーバーはAPIリクエスト（`/api/*`）とWebSocket接続（`/ws`）をポート28888で実行されているGoバックエンドにプロキシします。

## 📊 使用統計とプライバシー保護

QuantMeshには、匿名の使用データを収集するオプションの使用統計機能が含まれており、プロジェクトの使用状況を理解し、製品を改善するのに役立ちます。**すべてのデータ収集は完全に透明で、コードは監査可能で、いつでも無効にできます。**

### 🔒 プライバシー保護

**収集するデータ（匿名）:**
- ✅ **基本情報**: バージョン番号、オペレーティングシステム、アーキテクチャ、インスタンスID（ランダムに生成されたUUID）
- ✅ **使用統計**: 使用された取引所名、取引ペア
- ✅ **パフォーマンスメトリクス**: APIリクエスト/レスポンスレイテンシ、WebSocketレイテンシ
- ✅ **取引活動**: 取引方向（買い/売り）、取引金額を除く

**収集しないデータ:**
- ❌ **IPアドレス**: フロントエンドはIPキャプチャが無効、バックエンドはIPの代わりにインスタンスIDを使用
- ❌ **位置情報**: 緯度/経度、都市、その他の位置情報の収集なし
- ❌ **個人情報**: ユーザーID、メール、名前、または任意の識別情報の収集なし
- ❌ **機密データ**: APIキー、取引金額、アカウント残高、またはポジション情報の収集なし
- ❌ **財務データ**: 財務または取引機密情報の収集なし

### 🛡️ プライバシー保護措置

1. **インスタンスIDメカニズム**: ランダムに生成されたUUIDを一意の識別子として使用、`./data/instance_id`ファイルに保存、個人情報を含まない
2. **フロントエンドIP無効**: PostHog SDKが`ip_capture: false`で設定、IPアドレスキャプチャと位置情報推論を無効化
3. **バックエンドはIPを送信しない**: バックエンドコードは統計サービスにIPアドレスを送信しない
4. **完全にオプション**: ユーザーは環境変数を通じていつでも統計を無効にできる
5. **コードの透明性**: すべての統計コードは監査可能、`utils/telemetry.go`に配置

### ⚙️ 統計を無効にする方法

**方法1: 環境変数（推奨）**
```bash
export QUANTMESH_DISABLE_TELEMETRY=1
```

**方法2: フロントエンドを無効化**
`webui/.env.local`ファイルで:
```bash
VITE_DISABLE_TELEMETRY=1
```

**方法3: コードを変更**
`utils/telemetry.go`を編集し、`Enabled`を`false`に設定
