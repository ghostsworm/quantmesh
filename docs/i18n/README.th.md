## 📖 บทนำ

QuantMesh เป็นระบบ market maker สำหรับสกุลเงินดิจิทัลที่มีประสิทธิภาพสูงและความหน่วงต่ำ โดยมุ่งเน้นที่กลยุทธ์การซื้อขายแบบ grid ทิศทางเดียวสำหรับตลาดสัญญาถาวร พัฒนาด้วย Go และขับเคลื่อนด้วยสตรีมข้อมูลแบบเรียลไทม์ผ่าน WebSocket มีเป้าหมายเพื่อให้การสนับสนุนสภาพคล่องที่มั่นคงสำหรับ exchange หลักๆ เช่น Binance, Bitget และ Gate.io

หลังจากหลายครั้งของการพัฒนา เราได้ใช้ระบบนี้ซื้อขายสกุลเงินเสมือนมากกว่า $100 ล้าน ตัวอย่างเช่น การซื้อขาย Binance ETHUSDC โดยไม่มีค่าธรรมเนียม ช่วงราคา $1 และ $300 ต่อคำสั่ง ปริมาณการซื้อขายรายวันสามารถเกิน $3 ล้าน และมากกว่า $50 ล้านต่อเดือน ตราบใดที่ตลาดแกว่งหรือมีแนวโน้มขึ้น จะยังคงสร้างผลกำไรต่อไป หากตลาดตกด้านเดียว $30,000 ในมาร์จิ้นสามารถรับประกันว่าจะไม่มีการล้างพอร์ตสำหรับการตก 1000 จุด ผ่านการซื้อขายอย่างต่อเนื่องเพื่อลดต้นทุน การฟื้นตัว 50% ก็เพียงพอที่จะคุ้มทุน และกลับไปที่ราคาเปิดเดิมสามารถสร้างผลกำไรได้มาก หากมีการตกอย่างรวดเร็วด้านเดียว ระบบควบคุมความเสี่ยงแบบแอคทีฟจะระบุและหยุดการซื้อขายทันที อนุญาตให้คำสั่งต่อเนื่องได้เมื่อตลาดฟื้นตัวเท่านั้น โดยไม่ต้องกังวลเรื่องการล้างพอร์ตจากราคาสูงสุด

ตัวอย่าง: เริ่มซื้อขาย ETH ที่ 3000 จุด ราคาตกลงไปที่ 2700 จุด สูญเสียประมาณ $3,000 เมื่อราคาฟื้นตัวไปที่มากกว่า 2850 จุด ก็จะคุ้มทุน กลับไปที่ 3000 จุด กำไรอยู่ในช่วง $1,000 ถึง $3,000

## 📜 ที่มาของโปรเจกต์

โปรเจกต์นี้พัฒนาขึ้นครั้งแรกโดยอิงจาก [OpenSQT Market Maker](https://github.com/dennisyang1986/opensqt_market_maker) ที่เผยแพร่โดย [dennisyang1986](https://github.com/dennisyang1986) ภายใต้สัญญาอนุญาต MIT

จากโปรเจกต์เดิม เราได้ทำการปรับปรุงและขยายความสามารถหลักดังนี้:

- ✨ **อินเทอร์เฟซ Frontend แบบสมบูรณ์**: เพิ่มอินเทอร์เฟซการจัดการเว็บ React + TypeScript ที่ให้การตรวจสอบการซื้อขายแบบภาพ การจัดการการตั้งค่า และการวิเคราะห์ข้อมูล
- 🏦 **การขยาย Exchange**: ขยายจาก 3 exchange (Binance, Bitget, Gate.io) ในโปรเจกต์เดิมเป็น **20+ exchange หลัก**
- 🔒 **ความเสถียรระดับการเงิน**: ปรับปรุงความน่าเชื่อถือของระบบอย่างครอบคลุม รวมถึงการจัดการข้อผิดพลาดที่ครอบคลุม กลไกความปลอดภัยแบบพร้อมกัน การรับประกันความสอดคล้องของข้อมูล การกู้คืนอัตโนมัติ ฯลฯ
- 📊 **การตรวจสอบที่เพิ่มขึ้น**: ระบบบันทึกที่ปรับปรุง การรวบรวมเมตริก (Prometheus) การตรวจสอบสุขภาพ และการแจ้งเตือนแบบเรียลไทม์
- 🛡️ **การควบคุมความเสี่ยงที่เสริมความแข็งแกร่ง**: การตรวจสอบความเสี่ยงแบบหลายชั้น การกระทบยอดอัตโนมัติ การตัดวงจรความผิดปกติ และการปกป้องความปลอดภัยของเงินทุน
- 🔌 **ระบบปลั๊กอิน**: รองรับกลไกปลั๊กอินที่ขยายได้สำหรับการปรับแต่งที่ง่ายและการพัฒนารอง
- 📱 **รองรับการสากล**: อินเทอร์เฟซหลายภาษา (จีน/อังกฤษ) รองรับ i18n
- 🧪 **รองรับ Testnet**: รองรับสภาพแวดล้อม testnet ของหลาย exchange สำหรับการพัฒนาและการทดสอบ

## ✨ คุณสมบัติหลัก

- **รองรับหลาย Exchange**: เข้ากันได้กับ Binance, Bitget, Gate.io, Bybit, EdgeX และแพลตฟอร์มหลักอื่นๆ
- **การตอบสนองระดับมิลลิวินาที**: ขับเคลื่อนด้วย WebSocket เต็มรูปแบบ (ข้อมูลตลาดและสตรีมคำสั่ง) ขจัดความล่าช้าในการ polling
- **กลยุทธ์ Grid อัจฉริยะ**: 
  - **โหมดจำนวนคงที่**: การใช้ทุนที่ควบคุมได้มากขึ้น
  - **ระบบ Super Slot**: จัดการสถานะคำสั่งและตำแหน่งอย่างชาญฉลาด ป้องกันความขัดแย้งแบบพร้อมกัน
- **ระบบควบคุมความเสี่ยงที่ทรงพลัง**:
  - **การควบคุมความเสี่ยงแบบแอคทีฟ**: ตรวจสอบความผิดปกติของปริมาณ K-line แบบเรียลไทม์ หยุดการซื้อขายอัตโนมัติ
  - **ความปลอดภัยของเงินทุน**: ตรวจสอบยอดคงเหลือ เลเวอเรจ และความเสี่ยงตำแหน่งสูงสุดก่อนเริ่มต้นอัตโนมัติ
  - **การกระทบยอดอัตโนมัติ**: ซิงค์สถานะท้องถิ่นและ exchange เป็นประจำเพื่อรับประกันความสอดคล้องของข้อมูล
- **สถาปัตยกรรมพร้อมกันสูง**: โมเดลพร้อมกันที่มีประสิทธิภาพตาม Goroutine + Channel + Sync.Map

```
│   ├── factory.go             # แพทเทิร์น factory สำหรับสร้างอินสแตนซ์ exchange
│   ├── types.go               # โครงสร้างข้อมูลทั่วไป

│   ├── binance/               # การใช้งาน Binance
│   ├── bitget/                # การใช้งาน Bitget
│   └── gate/                  # การใช้งาน Gate.io
│
├── logger/                    # ระบบบันทึก
│   └── logger.go              # การบันทึกไฟล์ + การบันทึกคอนโซล
│
├── monitor/                   # การตรวจสอบราคา
│   └── price_monitor.go       # สตรีมราคาเฉพาะทั่วโลก
│
├── order/                     # ชั้นการดำเนินการคำสั่ง
│   └── executor_adapter.go    # ตัวดำเนินการคำสั่ง (จำกัดอัตรา + retry)
│
├── position/                  # การจัดการตำแหน่ง (แกนกลาง)
│   └── super_position_manager.go  # ผู้จัดการ super slot
│
├── safety/                    # ความปลอดภัยและการควบคุมความเสี่ยง
│   ├── safety.go              # การตรวจสอบความปลอดภัยก่อนเริ่มต้น

│   ├── reconciler.go          # การกระทบยอดตำแหน่ง
│   └── order_cleaner.go       # การทำความสะอาดคำสั่ง
│
└── utils/                     # ฟังก์ชันยูทิลิตี้
    └── orderid.go             # การสร้าง ID คำสั่งแบบกำหนดเอง
```

## แนวทางปฏิบัติที่ดีที่สุด

1. **สำหรับสถานะ VIP Exchange**: ระบบนี้เป็นเครื่องมือสร้างปริมาณ หากความผันผวนของราคาไม่มาก $3,000 ในมาร์จิ้นสามารถสร้างปริมาณการซื้อขาย $10 ล้านใน 2-3 วัน

2. **แนวทางปฏิบัติที่ดีที่สุดสำหรับผลกำไร**: เข้าสู่ตลาดหลังจากรอบการตก เริ่มซื้อตำแหน่งก่อน แล้วเริ่มซอฟต์แวร์ มันจะขาย grid ทีละ grid ขึ้นไปโดยอัตโนมัติ เมื่อตำแหน่งของคุณหมดแล้ว หยุดระบบ หากคุณไม่แน่ใจว่าตลาดปัจจุบันเป็นจุดต่ำ คุณสามารถเริ่มต้นโดยไม่มีตำแหน่งฐาน หากมันตกเพิ่มเติม เพิ่มตำแหน่งที่จุดต่ำและรีสตาร์ทเพื่อขายต่อ สิ่งนี้เพิ่มผลกำไรสูงสุด ทำซ้ำรอบนี้เพื่อผลกำไรอย่างต่อเนื่อง ไม่ต้องกังวลเรื่องการตก - โปรแกรมลดต้นทุนอย่างต่อเนื่อง ตราบใดที่มันฟื้นตัวครึ่งหนึ่ง คุณก็จะคุ้มทุน

## 🚀 เริ่มต้นใช้งาน

### ความต้องการเบื้องต้น
- Go 1.21 หรือสูงกว่า
- สภาพแวดล้อมเครือข่ายที่สามารถเข้าถึง API ของ exchange

### การติดตั้ง

1. **โคลน repository**
   ```bash
   git clone https://github.com/ghostsworm/quantmesh.git
   cd quantmesh
   ```

2. **ติดตั้ง dependencies**
   ```bash
   go mod download
   ```

### การตั้งค่า

> **Runtime SSOT:** The primary database table `app_config` holds the authoritative configuration. One-time YAML import: `./quantmesh --migrate-app-config` (with `QUANTMESH_IMPORT_YAML`, or `config.yaml` in the working directory), or run `./quantmesh /path/to/file.yaml` as the first argument. See [`docs/config-database-design.md`](../config-database-design.md).

1. คัดลอกไฟล์การตั้งค่าตัวอย่าง:
   ```bash
   cp docs/config/examples/config.example.yaml config.yaml
   ```

2. แก้ไข `config.yaml` และกรอก API Key และพารามิเตอร์กลยุทธ์ของคุณ:

   ```yaml
   app:
     current_exchange: "binance"  # เลือก exchange

   exchanges:
     binance:
       api_key: "YOUR_API_KEY"
       secret_key: "YOUR_SECRET_KEY"
       fee_rate: 0.0002

   trading:
     symbol: "ETHUSDT"       # คู่การซื้อขาย
     price_interval: 2       # ระยะห่าง grid (ราคา)
     order_quantity: 30     # จำนวนต่อ grid (USDT)
     buy_window_size: 10    # จำนวนคำสั่งซื้อ
     sell_window_size: 10   # จำนวนคำสั่งขาย
   ```

### การใช้งาน

#### โหมดการผลิต

รันไบนารีที่คอมไพล์แล้ว:

```bash
go run main.go
```

หรือสร้างและรัน:

```bash
go build -o quantmesh
./quantmesh
```

แบ็กเอนด์จะให้บริการไฟล์สแตติกของ frontend บนพอร์ต 28888 (ค่าเริ่มต้น)

#### โหมดการพัฒนา

สำหรับการพัฒนา frontend ด้วย hot reload และการดีบักซอร์สโค้ด:

**ตัวเลือก 1: ใช้สคริปต์การพัฒนา (แนะนำ)**

```bash
./scripts/local/dev.sh
```

สคริปต์นี้จะ:
- เริ่มเซิร์ฟเวอร์แบ็กเอนด์ Go บนพอร์ต 28888
- เริ่มเซิร์ฟเวอร์ dev Vite บนพอร์ต 15173
- เปิดใช้งาน hot reload สำหรับการเปลี่ยนแปลงโค้ด frontend
- ให้ source maps สำหรับการดีบัก (ไม่มีโค้ดที่ย่อ)

จากนั้นเข้าถึงแอปพลิเคชันที่: **http://localhost:15173**

**ตัวเลือก 2: เริ่มต้นด้วยตนเอง**

Terminal 1 - เริ่มแบ็กเอนด์ Go:
```bash
go run main.go
```

Terminal 2 - เริ่มเซิร์ฟเวอร์ dev Vite:
```bash
cd webui
pnpm dev
```

จากนั้นเข้าถึงแอปพลิเคชันที่: **http://localhost:15173**

**ข้อดีของโหมดการพัฒนา:**
- ✅ Hot reload - การเปลี่ยนแปลงโค้ด frontend สะท้อนทันที
- ✅ Source maps - ดีบักด้วยโค้ด TypeScript/React เดิม (ไม่ย่อ)
- ✅ Fast refresh - คอมโพเนนต์ React อัปเดตโดยไม่สูญเสียสถานะ
- ✅ ข้อความข้อผิดพลาดที่ดีขึ้น - ดูชื่อไฟล์และหมายเลขบรรทัดจริง

**หมายเหตุ:** ในโหมดการพัฒนา เซิร์ฟเวอร์ dev Vite จะทำหน้าที่เป็นพร็อกซี่สำหรับคำขอ API (`/api/*`) และการเชื่อมต่อ WebSocket (`/ws`) ไปยังแบ็กเอนด์ Go ที่ทำงานบนพอร์ต 28888

## 📊 สถิติการใช้งานและการปกป้องความเป็นส่วนตัว

QuantMesh รวมฟีเจอร์สถิติการใช้งานแบบเลือกได้เพื่อรวบรวมข้อมูลการใช้งานแบบไม่ระบุตัวตน ช่วยให้เราเข้าใจการใช้งานโปรเจกต์และปรับปรุงผลิตภัณฑ์ **การรวบรวมข้อมูลทั้งหมดโปร่งใส โค้ดตรวจสอบได้ และสามารถปิดการใช้งานได้ตลอดเวลา**

### 🔒 การปกป้องความเป็นส่วนตัว

**ข้อมูลที่เรารวบรวม (ไม่ระบุตัวตน):**
- ✅ **ข้อมูลพื้นฐาน**: หมายเลขเวอร์ชัน ระบบปฏิบัติการ สถาปัตยกรรม ID อินสแตนซ์ (UUID ที่สร้างแบบสุ่ม)
- ✅ **สถิติการใช้งาน**: ชื่อ exchange ที่ใช้ คู่การซื้อขาย
- ✅ **ตัวชี้วัดประสิทธิภาพ**: ความหน่วงการร้องขอ/ตอบสนอง API ความหน่วง WebSocket
- ✅ **กิจกรรมการซื้อขาย**: ทิศทางการซื้อขาย (ซื้อ/ขาย) ไม่รวมจำนวนการซื้อขาย

**ข้อมูลที่เราไม่รวบรวม:**
- ❌ **ที่อยู่ IP**: Frontend ปิดการจับ IP แบ็กเอนด์ใช้ ID อินสแตนซ์แทน IP
- ❌ **ตำแหน่งทางภูมิศาสตร์**: ไม่รวบรวมละติจูด/ลองจิจูด เมือง หรือข้อมูลตำแหน่งอื่นๆ
- ❌ **ข้อมูลส่วนบุคคล**: ไม่รวบรวม ID ผู้ใช้ อีเมล ชื่อ หรือข้อมูลประจำตัวใดๆ
- ❌ **ข้อมูลที่ละเอียดอ่อน**: ไม่รวบรวมคีย์ API จำนวนการซื้อขาย ยอดคงเหลือบัญชี หรือข้อมูลตำแหน่ง
- ❌ **ข้อมูลทางการเงิน**: ไม่รวบรวมข้อมูลทางการเงินหรือข้อมูลที่ละเอียดอ่อนของการซื้อขาย

### 🛡️ มาตรการปกป้องความเป็นส่วนตัว

1. **กลไก ID อินสแตนซ์**: ใช้ UUID ที่สร้างแบบสุ่มเป็นตัวระบุเฉพาะ เก็บในไฟล์ `./data/instance_id` ไม่มีข้อมูลส่วนบุคคล
2. **IP Frontend ถูกปิด**: PostHog SDK กำหนดค่าด้วย `ip_capture: false` ปิดการจับที่อยู่ IP และการอนุมานตำแหน่งทางภูมิศาสตร์
3. **แบ็กเอนด์ไม่ส่ง IP**: โค้ดแบ็กเอนด์ไม่ส่งที่อยู่ IP ไปยังบริการสถิติ
4. **เป็นทางเลือกทั้งหมด**: ผู้ใช้สามารถปิดสถิติได้ตลอดเวลาผ่านตัวแปรสภาพแวดล้อม
5. **ความโปร่งใสของโค้ด**: โค้ดสถิติทั้งหมดตรวจสอบได้ อยู่ใน `utils/telemetry.go`

### ⚙️ วิธีปิดการใช้งานสถิติ

**วิธีที่ 1: ตัวแปรสภาพแวดล้อม (แนะนำ)**
```bash
export QUANTMESH_DISABLE_TELEMETRY=1
```

**วิธีที่ 2: ปิด Frontend**
ในไฟล์ `webui/.env.local`:
```bash
VITE_DISABLE_TELEMETRY=1
```

**วิธีที่ 3: แก้ไขโค้ด**
แก้ไข `utils/telemetry.go` ตั้งค่า `Enabled` เป็น `false`
