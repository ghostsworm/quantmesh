## 📖 معرفی

QuantMesh یک سیستم سازنده بازار رمزنگاری با عملکرد بالا و تأخیر کم است که بر استراتژی‌های معاملات شبکه‌ای بلند برای بازارهای قرارداد دائمی تمرکز دارد. در Go توسعه یافته و توسط جریان‌های داده بلادرنگ WebSocket هدایت می‌شود، هدف آن ارائه پشتیبانی نقدینگی پایدار برای صرافی‌های بزرگ مانند Binance، Bitget و Gate.io است.

پس از چندین تکرار، از این سیستم برای معامله بیش از $100 میلیون ارز مجازی استفاده کرده‌ایم. به عنوان مثال، معامله Binance ETHUSDC با هزینه صفر، فاصله قیمت $1 و $300 برای هر سفارش، حجم معاملات روزانه می‌تواند از $3 میلیون تجاوز کند و بیش از $50 میلیون در ماه. تا زمانی که بازار در نوسان است یا روند صعودی دارد، به تولید سود ادامه خواهد داد. اگر بازار یک طرفه سقوط کند، $30,000 در حاشیه می‌تواند عدم نقدینگی برای کاهش 1000 امتیاز را تضمین کند. از طریق معاملات مداوم برای کاهش هزینه‌ها، بهبود 50% برای رسیدن به نقطه سر به سر کافی است و بازگشت به قیمت افتتاحیه اصلی می‌تواند سود قابل توجهی ایجاد کند. اگر کاهش سریع یک طرفه وجود داشته باشد، سیستم کنترل ریسک فعال به طور خودکار شناسایی می‌کند و فوراً معاملات را متوقف می‌کند، فقط اجازه سفارشات مداوم را می‌دهد زمانی که بازار بهبود می‌یابد، بدون نگرانی از نقدینگی از قله‌های قیمت.

مثال: شروع معامله ETH در 3000 امتیاز، قیمت به 2700 امتیاز می‌رسد، از دست دادن تقریباً $3,000. وقتی قیمت به بالای 2850 امتیاز بهبود می‌یابد، به نقطه سر به سر می‌رسد. بازگشت به 3000 امتیاز، سود از $1,000 تا $3,000 متغیر است.

## 📜 منشاء پروژه

این پروژه در اصل بر اساس [OpenSQT Market Maker](https://github.com/dennisyang1986/opensqt_market_maker) توسعه یافت که توسط [dennisyang1986](https://github.com/dennisyang1986) تحت مجوز MIT منتشر شد.

بر اساس پروژه اصلی، بهبودها و گسترش‌های اصلی زیر را انجام داده‌ایم:

- ✨ **رابط Frontend کامل**: یک رابط مدیریت وب React + TypeScript اضافه شد که نظارت بصری معاملات، مدیریت پیکربندی و تجزیه و تحلیل داده را ارائه می‌دهد
- 🏦 **گسترش صرافی**: از 3 صرافی (Binance، Bitget، Gate.io) در پروژه اصلی به **20+ صرافی بزرگ** گسترش یافت
- 🔒 **پایداری سطح مالی**: قابلیت اطمینان سیستم به طور جامع بهبود یافت، شامل مدیریت خطای جامع، مکانیزم‌های ایمنی همزمانی، تضمین‌های سازگاری داده، بازیابی خودکار و غیره
- 📊 **نظارت پیشرفته**: سیستم ثبت پیشرفته، جمع‌آوری معیارها (Prometheus)، بررسی‌های سلامت و هشدارهای بلادرنگ
- 🛡️ **کنترل ریسک تقویت شده**: نظارت ریسک چندلایه، تطبیق خودکار، قطع مدار ناهنجاری و محافظت از امنیت وجوه
- 🔌 **سیستم افزونه**: پشتیبانی از مکانیزم‌های افزونه قابل گسترش برای سفارشی‌سازی آسان و توسعه ثانویه
- 📱 **پشتیبانی بین‌المللی‌سازی**: رابط چندزبانه (چینی/انگلیسی)، پشتیبانی i18n
- 🧪 **پشتیبانی Testnet**: پشتیبانی از محیط‌های testnet چندین صرافی برای توسعه و آزمایش

برای توضیحات بهبود تفصیلی و اطلاعات نرم‌افزار شخص ثالث، لطفاً به فایل [NOTICE](../../NOTICE) مراجعه کنید.

## ✨ ویژگی‌های کلیدی

- **پشتیبانی چند صرافی**: سازگار با Binance، Bitget، Gate.io، Bybit، EdgeX و سایر پلتفرم‌های بزرگ.
- **پاسخ سطح میلی‌ثانیه**: کاملاً هدایت شده توسط WebSocket (داده‌های بازار و جریان سفارش)، حذف تأخیرهای polling.
- **استراتژی شبکه هوشمند**: 
  - **حالت مبلغ ثابت**: استفاده از سرمایه قابل کنترل‌تر.
  - **سیستم Super Slot**: به طور هوشمند وضعیت‌های سفارش و موقعیت را مدیریت می‌کند، جلوگیری از درگیری‌های همزمانی.
- **سیستم کنترل ریسک قدرتمند**:
  - **کنترل ریسک فعال**: نظارت بلادرنگ بر ناهنجاری‌های حجم K-line، به طور خودکار معاملات را متوقف می‌کند.
  - **امنیت وجوه**: به طور خودکار موجودی، اهرم و حداکثر ریسک موقعیت را قبل از راه‌اندازی بررسی می‌کند.
  - **تطبیق خودکار**: به طور منظم وضعیت‌های محلی و صرافی را همگام‌سازی می‌کند تا سازگاری داده را تضمین کند.
- **معماری همزمانی بالا**: مدل همزمانی کارآمد بر اساس Goroutine + Channel + Sync.Map.

## بهترین شیوه‌ها

1. **برای وضعیت VIP صرافی**: این سیستم یک ابزار تولید حجم است. اگر نوسانات قیمت بزرگ نباشد، $3,000 در حاشیه می‌تواند $10 میلیون حجم معاملات را در 2-3 روز تولید کند.

2. **بهترین شیوه برای سود**: پس از یک دور کاهش وارد بازار شوید. ابتدا یک موقعیت بخرید، سپس نرم‌افزار را شروع کنید. به طور خودکار شبکه به شبکه به سمت بالا می‌فروشد. وقتی موقعیت شما فروخته شد، سیستم را متوقف کنید. اگر مطمئن نیستید که بازار فعلی یک نقطه پایین است، می‌توانید بدون موقعیت پایه شروع کنید. اگر بیشتر سقوط کند، یک موقعیت در نقطه پایین اضافه کنید و برای ادامه فروش راه‌اندازی مجدد کنید. این سود را به حداکثر می‌رساند. این چرخه را برای سود مداوم تکرار کنید. نگران کاهش‌ها نباشید - برنامه به طور مداوم هزینه‌ها را کاهش می‌دهد. تا زمانی که نیمی بهبود یابد، به نقطه سر به سر می‌رسید.

## 🚀 شروع

### پیش‌نیازها
- Go 1.21 یا بالاتر
- محیط شبکه قادر به دسترسی به API های صرافی

### نصب

1. **کلون کردن مخزن**
   ```bash
   git clone https://github.com/ghostsworm/quantmesh.git
   cd quantmesh
   ```

2. **نصب وابستگی‌ها**
   ```bash
   go mod download
   ```

### پیکربندی

> **Runtime SSOT:** The primary database table `app_config` holds the authoritative configuration. One-time YAML import: `./quantmesh --migrate-app-config` (with `QUANTMESH_IMPORT_YAML`, or `config.yaml` in the working directory), or run `./quantmesh /path/to/file.yaml` as the first argument. See [`docs/config-database-design.md`](../config-database-design.md).

1. فایل پیکربندی نمونه را کپی کنید:
   ```bash
   cp docs/config/examples/config.example.yaml config.yaml
   ```

2. `config.yaml` را ویرایش کنید و کلید API و پارامترهای استراتژی خود را پر کنید:

   ```yaml
   app:
     current_exchange: "binance"  # صرافی را انتخاب کنید

   exchanges:
     binance:
       api_key: "YOUR_API_KEY"
       secret_key: "YOUR_SECRET_KEY"
       fee_rate: 0.0002

   trading:
     symbol: "ETHUSDT"       # جفت معاملاتی
     price_interval: 2       # فاصله شبکه (قیمت)
     order_quantity: 30     # مبلغ برای هر شبکه (USDT)
     buy_window_size: 10    # تعداد سفارشات خرید
     sell_window_size: 10   # تعداد سفارشات فروش
   ```

### استفاده

#### حالت تولید

اجرای باینری کامپایل شده:

```bash
go run main.go
```

یا build و اجرا:

```bash
go build -o quantmesh
./quantmesh
```

بک‌اند فایل‌های استاتیک frontend را در پورت 28888 (پیش‌فرض) ارائه می‌دهد.

#### حالت توسعه

برای توسعه frontend با hot reload و اشکال‌زدایی کد منبع:

**گزینه 1: استفاده از اسکریپت توسعه (توصیه می‌شود)**

```bash
./scripts/local/dev.sh
```

این اسکریپت:
- سرور بک‌اند Go را در پورت 28888 راه‌اندازی می‌کند
- سرور dev Vite را در پورت 15173 راه‌اندازی می‌کند
- hot reload را برای تغییرات کد frontend فعال می‌کند
- نقشه‌های منبع را برای اشکال‌زدایی ارائه می‌دهد (بدون کد minify شده)

سپس به برنامه در دسترسی پیدا کنید: **http://localhost:15173**

**گزینه 2: راه‌اندازی دستی**

ترمینال 1 - شروع بک‌اند Go:
```bash
go run main.go
```

ترمینال 2 - شروع سرور dev Vite:
```bash
cd webui
pnpm dev
```

سپس به برنامه در دسترسی پیدا کنید: **http://localhost:15173**

**مزایای حالت توسعه:**
- ✅ Hot reload - تغییرات کد frontend فوراً منعکس می‌شود
- ✅ نقشه‌های منبع - اشکال‌زدایی با کد TypeScript/React اصلی (minify نشده)
- ✅ تازه‌سازی سریع - مؤلفه‌های React بدون از دست دادن وضعیت به‌روزرسانی می‌شوند
- ✅ پیام‌های خطای بهتر - نام فایل‌ها و شماره خطوط واقعی را ببینید

**یادداشت:** در حالت توسعه، سرور dev Vite درخواست‌های API (`/api/*`) و اتصالات WebSocket (`/ws`) را به بک‌اند Go که در پورت 28888 اجرا می‌شود، proxy می‌کند.

سیستم یک طراحی ماژولار با مؤلفه‌های اصلی شامل:

- **لایه صرافی**: انتزاع رابط صرافی یکپارچه، محافظت از تفاوت‌های API اساسی.
- **مانیتور قیمت**: منبع قیمت WebSocket منحصر به فرد جهانی، تضمین سازگاری تصمیم.

- **ایمنی و کنترل ریسک**: کنترل ریسک چندلایه، شامل بررسی‌های راه‌اندازی، نظارت زمان اجرا و قطع مدار ناهنجاری.

## 📊 آمار استفاده و محافظت از حریم خصوصی

QuantMesh شامل یک ویژگی آمار استفاده اختیاری برای جمع‌آوری داده‌های استفاده ناشناس است که به ما کمک می‌کند استفاده از پروژه را درک کنیم و محصول را بهبود بخشیم. **همه جمع‌آوری داده کاملاً شفاف است، کد قابل بررسی است و می‌تواند در هر زمان غیرفعال شود.**

### 🔒 محافظت از حریم خصوصی

**داده‌هایی که جمع‌آوری می‌کنیم (ناشناس):**
- ✅ **اطلاعات پایه**: شماره نسخه، سیستم عامل، معماری، شناسه نمونه (UUID تولید شده تصادفی)
- ✅ **آمار استفاده**: نام‌های صرافی استفاده شده، جفت‌های معاملاتی
- ✅ **معیارهای عملکرد**: تأخیر درخواست/پاسخ API، تأخیر WebSocket
- ✅ **فعالیت معاملاتی**: جهت معاملات (خرید/فروش)، به استثنای مبالغ معاملاتی

**داده‌هایی که جمع‌آوری نمی‌کنیم:**
- ❌ **آدرس IP**: Frontend دارای ضبط IP غیرفعال است، بک‌اند به جای IP از شناسه نمونه استفاده می‌کند
- ❌ **موقعیت جغرافیایی**: هیچ جمع‌آوری عرض/طول جغرافیایی، شهر یا اطلاعات مکان دیگر وجود ندارد
- ❌ **اطلاعات شخصی**: هیچ جمع‌آوری شناسه کاربر، ایمیل، نام یا هر اطلاعات هویتی وجود ندارد
- ❌ **داده‌های حساس**: هیچ جمع‌آوری کلیدهای API، مبالغ معاملاتی، موجودی حساب یا اطلاعات موقعیت وجود ندارد
- ❌ **داده‌های مالی**: هیچ جمع‌آوری اطلاعات مالی یا معاملاتی حساس وجود ندارد

### 🛡️ اقدامات محافظت از حریم خصوصی

1. **مکانیزم شناسه نمونه**: از UUID تولید شده تصادفی به عنوان شناسه منحصر به فرد استفاده می‌کند، در فایل `./data/instance_id` ذخیره می‌شود، شامل اطلاعات شخصی نیست
2. **IP Frontend غیرفعال**: PostHog SDK با `ip_capture: false` پیکربندی شده است، ضبط آدرس IP و استنتاج موقعیت جغرافیایی را غیرفعال می‌کند
3. **بک‌اند IP ارسال نمی‌کند**: کد بک‌اند آدرس‌های IP را به سرویس آمار ارسال نمی‌کند
4. **کاملاً اختیاری**: کاربران می‌توانند در هر زمان از طریق متغیرهای محیطی آمار را غیرفعال کنند
5. **شفافیت کد**: همه کد آمار قابل بررسی است، در `utils/telemetry.go` قرار دارد

### ⚙️ نحوه غیرفعال کردن آمار

**روش 1: متغیر محیطی (توصیه می‌شود)**
```bash
export QUANTMESH_DISABLE_TELEMETRY=1
```

**روش 2: غیرفعال کردن Frontend**
در فایل `webui/.env.local`:
```bash
VITE_DISABLE_TELEMETRY=1
```

**روش 3: تغییر کد**
ویرایش `utils/telemetry.go`، تنظیم `Enabled` به `false`
