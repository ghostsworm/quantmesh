# 事件中心动态控制功能

## 功能概述

在日志页面添加了事件中心状态显示和动态控制功能，允许用户通过 Web UI 实时查看和切换事件中心的运行状态。

## 功能特性

### 1. 状态显示
- 在日志页面顶部显示事件中心当前状态
- 状态指示器：
  - ✅ 运行中（绿色徽章）
  - ⏸️ 已停止（灰色徽章）
- 状态说明文字，清晰告知用户当前状态的含义

### 2. 动态控制
- 提供切换开关（Switch），支持一键启动/停止事件中心
- 操作实时生效，无需重启系统
- 操作结果通过 Toast 通知反馈给用户

### 3. 防护机制
- 防止重复启动：如果事件中心已在运行，再次调用 Start() 会直接返回
- 防止重复停止：如果事件中心未运行，调用 Stop() 会直接返回
- 线程安全：使用互斥锁保护状态变更
- 优雅关闭：确保所有 goroutine 正常退出

## 技术实现

### 后端 API

#### 1. 获取事件中心状态
```
GET /api/events/center/status
```

响应示例：
```json
{
  "enabled": true
}
```

#### 2. 设置事件中心状态
```
POST /api/events/center/status
Content-Type: application/json

{
  "enabled": true
}
```

响应示例：
```json
{
  "success": true,
  "enabled": true,
  "message": "事件中心已启动"
}
```

### 前端实现

#### 组件位置
`webui/src/components/Logs.tsx`

#### 主要功能
1. **状态加载**：页面加载时自动获取事件中心状态
2. **状态显示**：使用 Chakra UI 组件展示状态信息
3. **状态切换**：通过 Switch 组件切换状态
4. **错误处理**：操作失败时显示错误提示并恢复原状态

### 核心代码修改

#### 1. EventCenter 结构体增强
```go
type EventCenter struct {
    // ... 原有字段
    running bool      // 运行状态标志
    mu      sync.Mutex // 互斥锁
}
```

#### 2. Start/Stop 方法改进
- 添加运行状态检查
- 支持重复调用而不会出错
- 动态创建和取消 context

#### 3. 新增 IsRunning 方法
```go
func (ec *EventCenter) IsRunning() bool {
    ec.mu.Lock()
    defer ec.mu.Unlock()
    return ec.running
}
```

## 使用场景

### 场景 1：调试模式
在调试问题时，可以临时关闭事件中心以减少日志噪音，调试完成后再重新启用。

### 场景 2：性能优化
在系统负载较高时，可以临时关闭事件中心以减少数据库写入压力。

### 场景 3：按需记录
只在需要分析系统行为时启用事件中心，平时保持关闭以节省存储空间。

### 场景 4：故障排查
发现系统异常时，快速启用事件中心开始记录详细事件，便于后续分析。

## 配置说明

### 配置文件
主配置（Web / **`app_config`** / 导入 YAML）中的 `event_center.enabled` 字段控制系统启动时的默认状态：

```yaml
event_center:
  enabled: false  # 系统启动时不自动启动事件中心
```

### 动态控制
无论配置文件中的设置如何，都可以通过 Web UI 动态启动或停止事件中心。

## 注意事项

1. **数据一致性**：停止事件中心后，系统产生的事件将不会被记录到数据库
2. **实时性**：状态切换立即生效，无需等待
3. **持久性**：通过 Web UI 修改的状态不会保存到配置文件，系统重启后会恢复配置文件中的设置
4. **权限要求**：需要登录认证才能访问事件中心控制接口

## 测试步骤

### 4. 切换状态
点击 Switch 开关，观察：
- 状态徽章颜色变化
- Toast 通知提示

### 5. 验证功能
- 启用事件中心后，访问事件中心页面应该能看到新事件
- 停用事件中心后，新产生的系统事件不会被记录

## 故障排查

### 问题：切换开关无响应
- 检查浏览器控制台是否有错误
- 检查后端日志是否有错误信息
- 确认用户已登录且有权限

### 问题：状态显示不准确
- 刷新页面重新加载状态
- 检查后端 API 是否正常响应

### 问题：启动失败
- 检查数据库是否正常连接
- 检查后端日志中的错误信息
