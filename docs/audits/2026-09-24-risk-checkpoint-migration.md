# 风险高水位表迁移（未发布）

适用版本：3.111.0-rc2。此迁移尚未在生产数据库执行。

正常应用启动**不会自动创建** `risk_checkpoints`。缺表、查询失败、损坏记录都不是“第一次启动”，不得静默创建新高水位。未完成迁移时，权益健康状态报错；启用回撤风控的 Bot 保持新开仓暂停。

## 显式迁移步骤

1. 获得目标环境的变更批准；确认数据库类型与目标实例，备份现有数据库。不得把真实 DSN、密码或访问密钥写进命令记录、工单或仓库。
2. 用只读方式确认表是否存在；若已存在且有风险历史，先导出该表，不得以清空/重建方式修复数据错误。
3. 审查并在测试数据库演练对应 SQL，再通过已认证的数据库管理工具在批准的维护窗口执行：
   - SQLite：`storage/migrations/2026092401_risk_checkpoints_sqlite.up.sql`
   - MySQL：`storage/migrations/2026092401_risk_checkpoints_mysql.up.sql`
4. 确认字段、唯一键和读写权限。应用先保存采样游标、高水位、现金流凭据，再发布风险指标；并发版本冲突需重新读取，不允许覆盖较新状态。
5. 验收断电/重启、写入失败、并发版本冲突、缺表/损坏状态，以及健康 API。表迁移成功不等于交易所现金流水已经接齐，`cash_flow_adjusted=false` 时仍不得放行回撤风控。

SQLite 上下迁移、幂等和真实文件重开由自动化测试覆盖；MySQL SQL 已提供，但尚未在 MySQL 实例执行验收。

## 回滚

两个 `.down.sql` 文件都会删除风险历史表，**必须先停用相关写入并备份表数据，经批准后才能执行**。回滚之后不可在旧版本重启时把风险基线归零继续无人值守交易；应先恢复历史或进入明确的人工对账流程。应用版本回滚通常优先保留本表，无需执行 down。

## 当前边界

- 当前现金流计算核心以固定基准的绝对权益剔除净外部入出金，不是份额化/TWR 收益率；手续费、资金费、借息保留在真实权益中，不重复扣除。
- Binance USDT 单资产运行时已接分页流水与精确钱包差额核账，检查点 JSON 保存每账户钱包基准、远端游标和流水凭据。本批不增加数据库表或自动迁移。只有核账、保存成功的完整账户集合才能发布已调整权益，混合未支持的交易所仍不得放行。
- 旧的无钱包证明检查点不能自动转换或重建高水位。升级后的模式变更需经历史核账和明确确认；不得通过删表/删记录解除暂停。账户集合或估值币种改变，即使普通手动恢复也不能自动重设范围。
- 其他交易所接入、历史更正重放、现货估值和与 Bot 生命周期解耦的稳定账户集合仍在整改；不要以已通过核心单测或已建表为实盘验收依据。
