# 小时波动率证据与运行时准入

版本：`3.111.0-rc10`，未发布。此文定义统计口径和数据健康边界，不是盈利或实盘放行报告。

## 固定时间口径

- ShortPeriod、MediumPeriod、LongPeriod 的单位是小时。只消费已闭合的一小时 K 线，不以 WebSocket 消息数或价格推送间隔替代时间。
- `PricePoint.Timestamp` 为该小时的 UTC 闭合边界。交易所适配器提供毫秒开盘时间，加载器明确加一小时转换；当前未闭合 K 线即使被适配器标成 IsClosed=true 也不纳入。
- N 小时波动率需要 N+1 个连续小时收盘价，计算 N 个简单收益率 `r[i] = 100 * (close[i] / close[i-1] - 1)` 的总体标准差：`sqrt(sum((r[i] - mean(r))²) / N)`。单位为百分比，不年化，也不乘 sqrt(N)。
- 价格范围使用配置小时数内已闭合 K 线的最高价、最低价，计算 `(max(high) - min(low)) / min(low) * 100`。不裁剪大幅波动，不用当前未闭合柱补齐历史。
- 全部配置窗口均须完整。启动加载条数为 `max(各窗口小时数) + max(连续确认数, 2) + 1`，额外历史用于区间确认和前后两次小时统计比较。重复加载同一个小时不推进确认次数。
- 实时 tick 只更新报价新鲜度及 Bot 趋势时间窗；小时波动率不会因每秒接收 1 条还是 1,000 条报价而变化。该小时模型**不替代逐 tick 止损、突发行情保护或在途硬额度**。

## 加载、校验与发布

1. 当前运行时绑定自己的交易所对象和交易对，在首次网格调整/策略启动前创建受管历史加载器；配置启用保护但证据不足时不开新仓，持仓保护继续运行。
2. 请求 `1h` 历史；Bybit 与 OKX 的现货/合约适配器分别转换为各自的小时周期值。加载器排序并校验交易对、闭合时间及 OHLC/成交量有限性；检测器原子校验连续性、长度和最新闭合小时。
3. 拒绝缺口、重复、乱序、NaN/Inf、未来柱、缺失最后闭合小时。已在当前进程接受的重叠闭合柱若价格/高低点/成交量改变，必须先核实，不能静默覆盖。
4. 每个新小时重新加载；失败按 30 秒间隔重试，单次受 10 秒及运行时取消约束。历史请求不在行情锁下执行，返回时再次核验当前小时，跨整点的旧响应不能假报最新。
5. 历史完整和实时报价新鲜是两个条件：历史加载成功不伪造新报价；很多新 tick 也不能掩盖缺失小时历史。两分钟内有效实时报价、当前闭合小时历史、当前配置和其他独立风险来源共同决定是否可恢复。
6. 历史重载失败保留旧统计供诊断，但不拿旧统计解除数据限制。停止时取消并等待历史工作协程；迟到结果不得修改已停止运行时。

`GetPositionStatus` 的 `volatility_evidence` 包含模型名称、所需闭合小时条数、`history_through`、`last_quote_at`、`ready` 及原因。`ready` 仅表示数据可用，不表示资金/订单已核账或允许开仓。

## 验证与未闭合范围

- 本地测试覆盖统计公式、重复加载幂等、增量/重启统计一致、报价频率不变、异常数据原子拒绝、整点刷新、取消，以及 Bybit/OKX 本地 HTTP 周期转换。实际回归报告见整改进度第十八批。
- 预设阈值沿用现有配置，**尚未针对这一明确口径做样本外校准**。遗留 NormalThreshold 的完整语义、突变阈值配置与全部动态调参策略仍需继续审计，不能将数据时钟修正当成全部参数有效性验收。
- 生产加载器目前为单页请求，需小于 1,000 根；交易所若返回不足条数会拒绝放行，不会缩短配置窗口。更长窗口分页、交易所各自历史长度限制及全部适配器验收仍待补。
- 重叠历史校验是本进程内的证据保护，不是跨重启持久审计。市场数据历史修正流程、策略成本/费用/资金恢复、完整配置版本/E2E 和盈利验收仍属原始整改范围。
- 未访问真实账户、进行交易、修改生产数据库或部署；原 R04/R05/R07/R09/R10/R12/R14/R15 等未完成项未因本批而关闭。
