## 功能概述

### 实时通知系统

支持多种通知方式：
- **Telegram Bot**: 最实时，推荐使用
- **Webhook**: 可对接钉钉、企业微信等
- **邮件**: 支持 SMTP、Resend、Mailgun

### 数据库存储

- **SQLite**: 轻量级，文件可拷贝
- **完全异步**: 不影响交易决策
- **自动批量写入**: 提高性能
- **保底方案**: 数据库失败时写入日志文件

## 通知系统配置

### 1. Telegram 配置

#### 步骤1: 创建 Telegram Bot

1. 在 Telegram 中搜索 `@BotFather`
2. 发送 `/newbot` 命令
3. 按提示设置 Bot 名称和用户名
4. 获取 Bot Token

#### 步骤2: 获取 Chat ID

1. 在 Telegram 中搜索 `@userinfobot`
2. 发送任意消息，获取你的 Chat ID

#### 步骤3: 配置

```yaml
notifications:
  enabled: true
  
  telegram:
    enabled: true
    bot_token: "123456789:ABCdefGHIjklMNOpqrsTUVwxyz"
    chat_id: "123456789"
```

### 2. Webhook 配置

```yaml
notifications:
  enabled: true
  
  webhook:
    enabled: true
    url: "https://your-webhook-url.com/api/notify"
    timeout: 3  # 超时时间（秒）
```

**Webhook 请求格式**:
```json
{
  "type": "order_filled",
  "timestamp": "2025-01-27T10:00:00Z",
  "data": {
    "order_id": 123456,
    "symbol": "ETHUSDT",
    "side": "BUY",
    "price": 3000.0,
    "quantity": 0.01
  }
}
```

### 3. 邮件配置

#### SMTP 配置

```yaml
notifications:
  enabled: true
  
  email:
    enabled: true
    provider: "smtp"
    
    smtp:
      host: "smtp.gmail.com"
      port: 587
      username: "your_email@gmail.com"
      password: "your_app_password"
    
    from: "alerts@yourdomain.com"
    to: "admin@yourdomain.com"
    subject: "QuantMesh 交易通知"
```

#### Resend 配置

```yaml
notifications:
  enabled: true
  
  email:
    enabled: true
    provider: "resend"
    
    resend:
      api_key: "re_xxxxxxxxxxxxx"
    
    from: "alerts@yourdomain.com"
    to: "admin@yourdomain.com"
```

**注意**: Resend 需要安装 `github.com/resend/resend-go/v2` 库

#### Mailgun 配置

```yaml
notifications:
  enabled: true
  
  email:
    enabled: true
    provider: "mailgun"
    
    mailgun:
      api_key: "key-xxxxxxxxxxxxx"
      domain: "your_domain.com"
    
    from: "alerts@yourdomain.com"
    to: "admin@yourdomain.com"
```

**注意**: Mailgun 需要安装 `github.com/mailgun/mailgun-go/v4` 库

### 4. 通知规则配置

```yaml
notifications:
  rules:
    order_placed: false    # 订单下单（默认关闭，避免通知过多）
    order_filled: true     # 订单成交（默认开启）
    risk_triggered: true   # 风控触发（默认开启）
    stop_loss: true        # 止损触发（默认开启）
    error: true            # 系统错误（默认开启）
```

## 数据库存储配置

### 基本配置

```yaml
storage:
  enabled: true               # 是否启用数据存储
  type: "sqlite"              # 存储类型（目前只支持 sqlite）
  path: "./data/quantmesh.db"   # 数据库文件路径
  buffer_size: 1000           # 缓冲区大小（默认1000）
  batch_size: 100             # 批量写入大小（默认100）
  flush_interval: 5           # 刷新间隔（秒，默认5）
```

### 配置说明

- **buffer_size**: 事件缓冲区大小，超过此数量会丢弃事件（不阻塞）
- **batch_size**: 达到此数量时立即批量写入数据库
- **flush_interval**: 定期刷新间隔，即使未达到批量大小也会定期写入

### 数据库文件位置

- 默认路径: `./data/quantmesh.db`
- 数据库文件可以随时拷贝和备份
- 建议定期备份数据库文件

## 使用示例

### 完整配置示例

```yaml
# 通知配置
notifications:
  enabled: true
  
  telegram:
    enabled: true
    bot_token: "YOUR_BOT_TOKEN"
    chat_id: "YOUR_CHAT_ID"
  
  webhook:
    enabled: false
    url: "https://your-webhook-url.com/api/notify"
    timeout: 3
  
  email:
    enabled: false
    provider: "smtp"
    smtp:
      host: "smtp.gmail.com"
      port: 587
      username: "your_email@gmail.com"
      password: "your_password"
    from: "alerts@yourdomain.com"
    to: "admin@yourdomain.com"
  
  rules:
    order_placed: false
    order_filled: true
    risk_triggered: true
    stop_loss: true
    error: true

# 存储配置
storage:
  enabled: true
  type: "sqlite"
  path: "./data/quantmesh.db"
  buffer_size: 1000
  batch_size: 100
  flush_interval: 5
```

### 启动系统

```bash
go run main.go
# 或显式传入导入 YAML：go run main.go my-import.yaml
```

系统会自动：
1. 初始化事件总线
2. 启动通知服务（如果启用）
3. 启动存储服务（如果启用）
4. 在关键位置发布事件

## 注意事项

### 1. 通知系统

- ✅ **完全异步**: 通知失败不会影响交易
- ✅ **超时控制**: 所有网络请求都有超时（3秒）
- ✅ **非阻塞**: 通知发送不会阻塞交易流程
- ⚠️ **Channel 满**: 如果事件队列满了，会丢弃事件并记录警告

### 2. 数据库存储

- ✅ **完全异步**: 数据库操作不会影响交易决策
- ✅ **批量写入**: 提高性能，减少数据库操作
- ✅ **保底方案**: 数据库失败时写入日志文件
- ⚠️ **数据目录**: 确保 `data/` 目录有写入权限
- ⚠️ **磁盘空间**: 定期检查磁盘空间，避免数据库文件过大

### 3. 性能考虑

- **缓冲区大小**: 根据系统负载调整 `buffer_size`
- **批量大小**: 根据交易频率调整 `batch_size`
- **刷新间隔**: 根据实时性要求调整 `flush_interval`

### 4. 故障处理

#### 通知失败

- 通知失败只记录警告日志，不影响交易
- 检查网络连接和配置是否正确
- 查看日志文件了解详细错误信息

#### 数据库失败

- 数据库失败时会自动降级到日志文件
- 检查日志文件: `./data/storage_fallback.log`
- 检查数据库文件权限和磁盘空间
- 数据库文件损坏时可以删除后重新创建

## 事件类型说明

系统会发布以下事件：

| 事件类型 | 说明 | 默认通知 |
|---------|------|---------|
| `order_placed` | 订单下单 | ❌ 关闭 |
| `order_filled` | 订单成交 | ✅ 开启 |
| `order_canceled` | 订单取消 | ❌ 关闭 |
| `risk_triggered` | 风控触发 | ✅ 开启 |
| `risk_recovered` | 风控解除 | ✅ 开启 |
| `stop_loss` | 止损触发 | ✅ 开启 |
| `take_profit` | 止盈触发 | ✅ 开启 |
| `error` | 系统错误 | ✅ 开启 |
| `system_start` | 系统启动 | ✅ 开启 |
| `system_stop` | 系统停止 | ✅ 开启 |

## 数据库表结构

### orders 表（订单表）

```sql
CREATE TABLE orders (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    order_id BIGINT UNIQUE,
    client_order_id TEXT,
    symbol TEXT,
    side TEXT,
    price DECIMAL(20,8),
    quantity DECIMAL(20,8),
    status TEXT,
    created_at TIMESTAMP,
    updated_at TIMESTAMP
);
```

### positions 表（持仓表）

```sql
CREATE TABLE positions (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    slot_price DECIMAL(20,8),
    symbol TEXT,
    size DECIMAL(20,8),
    entry_price DECIMAL(20,8),
    current_price DECIMAL(20,8),
    pnl DECIMAL(20,8),
    opened_at TIMESTAMP,
    closed_at TIMESTAMP
);
```

### trades 表（交易表）

```sql
CREATE TABLE trades (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    buy_order_id BIGINT,
    sell_order_id BIGINT,
    symbol TEXT,
    buy_price DECIMAL(20,8),
    sell_price DECIMAL(20,8),
    quantity DECIMAL(20,8),
    pnl DECIMAL(20,8),
    created_at TIMESTAMP
);
```

### events 表（事件表）

```sql
CREATE TABLE events (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    event_type TEXT,
    data TEXT,  -- JSON 格式
    created_at TIMESTAMP
);
```

### statistics 表（统计表）

```sql
CREATE TABLE statistics (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    date DATE UNIQUE,
    total_trades INTEGER,
    total_volume DECIMAL(20,8),
    total_pnl DECIMAL(20,8),
    win_rate DECIMAL(5,2),
    created_at TIMESTAMP
);
```

## 查询示例

### 查询最近的订单

```sql
SELECT * FROM orders 
ORDER BY created_at DESC 
LIMIT 10;
```

### 查询今日盈亏

```sql
SELECT 
    SUM(pnl) as total_pnl,
    COUNT(*) as trade_count
FROM trades 
WHERE DATE(created_at) = DATE('now');
```

### 查询风控触发记录

```sql
SELECT * FROM events 
WHERE event_type = 'risk_triggered'
ORDER BY created_at DESC;
```

## 总结

### 核心特性

1. **完全异步**: 所有操作不阻塞交易流程
2. **多种通知**: 支持 Telegram、Webhook、邮件
3. **数据持久化**: SQLite 数据库，文件可拷贝
4. **保底方案**: 数据库失败时写入日志文件
5. **可配置**: 灵活配置通知规则和存储参数

### 推荐配置

- **通知**: 优先使用 Telegram（最实时）
- **存储**: 启用 SQLite，定期备份数据库文件
- **规则**: 只通知重要事件，避免通知过多
